# 验证变更

读取 rules/verification.md、PROJECT.md、依赖脚本及 CI，确认真实可用命令。
根据 diff 和业务影响选择验证，避免无意义地重复全量测试。
接口看契约、核心逻辑看行为、UI 看交互、迁移看兼容性；文档改动检查链接与示例即可。

执行适当检查。失败时定位是否由当前变更引入，修复授权范围内的问题后重新运行相关检查。
没有命令或环境时记录限制，不虚构通过结果，不为了“有测试”而添加镜像实现的断言。

输出检查项、命令、通过或失败、未执行原因，以及影响交付的剩余风险。
